# 独立边界与连续变化审查

你是独立 reviewer，不是本轮关键形作者。先读工具 report.json，再打开它 visual_cases 列出的每张实际PNG图像、原 baseline 和必要的眼口放大图；最后用共用 preview 加载 compiled SVG + controls 并连续拖动所有公开参数。不能从源码推想画面，不能只看总览图或数值通过就给 pass。contact-sheet按页呈现只是导航；实际审图以visual_cases引用的原始PNG为准。

首先核对controls、scan_report和自身报告都声明capability_profile=basic-face-v1；capabilities须有12个轴的真实几何变化，以及两眼curve在open=0时的独立效果证据。数值非零只是排除空滑杆，不代表变化足够。审查必须覆盖controls实际keys的所有联合格点，不硬编码图片数量。

每个 case 核对参数值和图像一致，按照 report_schema 写 checked_cases。id 与 parameters 必须逐字对应 scan_report 的实际清单；image 使用相对本轮输出根的实际路径。observations 中分别写与原中性的保真关系、真实看到的眼睑接触、眼弧变化（eye_curve）、眉高/倾斜/曲率（brow_shape）、睫毛保持、邻域跟随、嘴部轮廓、开口遮罩、可用范围；当前case未涉及某部位时写明原因，不填无依据的“通过”。所有端点、组合角点和中间值都必须覆盖，不能只审作者最满意的样本。

明确否决以下结果：

- 闭眼存在白缝、接触边互穿，睫毛尖反向翻折，原睫毛束或眼角形状明显被改变。
- 闭眼后curve失效；眉高、倾斜、曲率缺项或只是重复同一变化；变化幅度接近不可见。
- 主要轮廓移动，但眼皮/眼眶阴影、唇周阴影、高光或裁剪停在原地；以“渐变复杂”解释几何错位不是通过理由。
- 张嘴最大值仍明显太小，嘴型正负值几乎没有可辨变化，或二维组合只有两条独立位移的叠加。
- 嘴唇、口腔和遮罩不同步，半开比全开更怪，嘴角裂开、牙舌穿出，闭口压成不符合原稿的黑线。
- 只在端点成立、内插时穿插或突然变化，复位不能回到原中性，或修改原SVG/新增器官掩盖问题。

正常面部尺度和放大局部都要看，不能靠缩小预览隐藏问题。可用范围是验收项，不能把变化缩到不可见来避免坏形变。

continuous_review 记录实际拖过的全部 parameter_ids、方法和观察结果，并保存真实预览截图/录屏或可追溯的浏览器检查记录。若未执行，performed=false；没有实际连续审查不能给 pass。数值扫描与浏览器观察分别报告，未测性能不得写60fps。只有静态工具可用时，如实交代缺项，不能伪称已拖动。

报告 task_id=review_boundaries。pass 的 issues 必须为空且所有case实际通过；revise 的每项issue必须含参数、SVG id、具体图像与修改建议，target=author_boundaries。发现程序插值/渲染内核问题时同样拒绝放行，在建议中标明工具责任，不指使作者重画原稿。缺证据/无法运行用blocked。

记录器会核对全部扫描case、实际图像和连续审查覆盖；它不会替你看图。技术连续、程序可复现、schema合法，都不是视觉合格的替代品。
