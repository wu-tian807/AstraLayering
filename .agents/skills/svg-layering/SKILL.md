# SVG Layering

本文件供总控调度使用。总控读取[流程顺序](references/流程.md)，选择节点、模型和输入；worker与reviewer读取各自节点提示词及其引用资料，按其中的步骤执行。

## 通用读取规则

- 模型由当前节点资料目录的 `*.model` **文件名**指定，文件可为空。
- 语言模型文件名格式为 `<模型ID>-<推理强度>.model`，从最右侧拆出推理强度。例如 `gpt-5.6-sol-xhigh.model` 对应 `model="gpt-5.6-sol"`、`reasoning_effort="xhigh"`；`gpt-6-astra-xhigh.model`同理。
- `image2.5.model`指定生图模型。含生图标记的节点由语言子agent调用对应生图入口，其余节点执行语言任务与程序操作。
- 提示词在当前节点资料目录匹配 `生成提示词.txt`、`提示词.txt`或 `*prompt.txt`，应只匹配一份。`.placeholder`描述所需输入，交接时绑定实际素材；`requirements.txt`列出工具依赖。
- 多step阶段查流程表指定的step目录；review查其review目录。每个节点资料目录应有且只有一个语言模型标记，配置缺失或冲突时先报告并解决。

调度者根据 `.model` 文件名填写调用参数；文件改名后，下次调度按新名字调用。skill根目录的标记建议调度会话使用Sol-xhigh，当前主会话模型由宿主设置决定。

## 工作根目录与最小交接

调度前确认用户提供的参考图（附件或可访问文件路径）和绝对输出路径。参考图缺失、无法访问或绝对输出路径未明确时，由总控一次询问缺项，获得答复后再开始；已有明确输入直接使用。续跑沿用用户指定案例中已确认的素材与根目录。

信息齐备后创建工作根目录。同一轮各节点的相对输入输出均以该目录为基准；脚本、readme等资料相对提示词所在目录查找。

交接只传本节点所需的路径、运行参数和用户补充要求：

```text
工作根目录：<绝对路径>
提示词：<绝对路径>
输入：<图号或用途＝实际路径，逐项列出>
读取指定提示词，按其步骤执行。相对输入输出以工作根目录为准，执行命令时将工作目录设为此处。
```

生图节点另附已确认的生图入口、模型与结果相对路径，交接中写明：**使用节点提示词原文生成一次，保存返回的原始图片后结束。** review另附候选快照、版本、SHA-256与证据相对目录。

## 调用与推进

1. 按用户目标确定起止节点。默认全流程到阶段5；明确只做平涂或到阶段4，就在阶段4review后结束。已有同版素材直接复用；输入版本不明确时向用户核实。
2. 起子agent时显式传入从文件名解析的模型和推理强度。当前若使用 `collaboration.spawn_agent`，设置 `model`、`reasoning_effort`、`fork_turns="none"`，再填写任务名和交接消息。使用其他接口时传等价参数。
3. 按最小交接模板派发worker，绑定本轮实际输入及图号。目录内示例文件仅在本轮选用时作为输入。
4. 等当前节点完成，记录实际输出路径、版本和worker会话ID，再交给下一节点。节点报告无法完成时，向用户说明卡点。
5. 按流程表在指定节点启动独立上下文的reviewer，交接其提示词与所需输入；工具在review提示词同目录。
6. reviewer要求返修时，用 `collaboration.followup_task` 或等价继续会话接口，把具体问题和证据交回**同一个worker**，修好再交原reviewer复验。reviewer可替换，替换时附前轮报告、候选版本和待复验问题；worker在同一返修循环中必须复用。
7. 复验通过且对应当前候选版本，才进入下一节点。参考歧义、必要检查缺失、连续返修无进展或原worker会话不可恢复时，报告卡点并暂停推进。

## 生图与资料

前置0—4使用节点文件原文作为生图提示词。派发前按生图标记确认入口的实际模型；无法确认时，说明缺少的入口，请用户提供对应结果或接入指定模型。

本skill的[workflows](workflows/)包含节点提示词、输入说明、参考素材、模型标记和review工具。完整复制skill目录即可携带执行资料；历史案例链接用于仓库内追溯。执行时资料包按只读使用，产物写入工作根目录，review证据单独保存。

格式依据：[Codex Skills](https://learn.chatgpt.com/docs/build-skills)；子agent模型设置依据：[Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)。
