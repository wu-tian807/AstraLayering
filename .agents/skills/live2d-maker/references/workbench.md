# 工作台启动与连接

在制作或续跑时，复用或启动真实工作台，展示同一 `<dir>/<name>` 的流程与产物，并把用户能访问的任务链接交给用户。CLI、HTTP 服务和宿主定时巡检是三个独立进程／任务；打开网页不会启动巡检，`pnpm start` 也不会自动启动网页。

## 定位或安装

先读任务的 `monitor.md`，复用已记录的工作台入口；本机默认端口为 4387。确认 `GET <工作台根URL>healthz` 返回 `status: "ok"`、`application: "astra-layering"`、`mode: "workbench"`，再读 `api/settings` 核对追踪目录。仅有端口响应不足以认定它是本工作台。远程工作台必须能访问任务所在的同一服务器文件系统，另一台机器上的同名路径不能替代。

完整仓库已经包含 `web/`、根 `package.json` 和 `pnpm-workspace.yaml`。独立安装的 skill 只有管线代码，不包含网页；若没有可复用的服务，在 skill 外准备一份工作台仓库，避免下载 demos/archive：

```bash
git clone --filter=blob:none --sparse https://github.com/wu-tian807/AstraLayering.git /安装位置/AstraLayering-web
cd /安装位置/AstraLayering-web
git sparse-checkout set web .agents/skills/live2d-maker
pnpm install --frozen-lockfile
```

稀疏检出也会保留根目录的 package、锁文件与 workspace 配置。已有完整仓库直接复用；依赖已安装且匹配锁文件时不重复安装。工作台尽量使用与执行管线相同的仓库版本。补齐网页不会搬迁已有任务，也不替换正在使用的 skill；后续 CLI 仍从原 skill 根目录执行，并显式传入原 `--dir`。

## 启动 HTTP 服务

从包含 `web/` 的仓库根目录执行，使用当前宿主可持续运行的后台进程或已有服务管理方式，保存日志与停止方式：

```bash
pnpm web
# 默认端口被其他服务占用时，可另选空闲端口
pnpm web --port 4388
```

这两条是二选一的启动示例；不重复启动已有健康服务。`pnpm web` 不接受工作流的 `--name` / `--dir`，目录在下一节设置。退出当前终端工具后也要能继续访问，不能把短时命令返回或进程 PID 当作服务就绪；检查 `healthz` 和实际任务页。

服务只监听 `127.0.0.1`。用户在同一台电脑时可以打开 `http://127.0.0.1:4387/`；远程执行时使用当前环境已有的端口转发、预览入口或部署代理，沿用其访问范围。代理根 URL 保留末尾 `/`，让页面与 API 的相对路径正确解析。远端的 localhost 不能直接当作用户的访问地址。

## 连接同一个任务

工作台每个实例只追踪一个运行根目录，保存在该仓库的 `.web/settings.json`。它应等于本次 CLI 的 `--dir`，其下一层才是任务 `<name>`。可在页面“工作目录”中设置；程序连接时使用：

| 请求（相对工作台根 URL） | 用途 |
| --- | --- |
| `GET api/settings` | 读取当前 `{ directory }` |
| `POST api/settings` | 设置追踪目录，JSON 见下方 |
| `GET api/tasks` | 核对返回的 `directory` 和任务列表 |
| `GET api/task?name=<编码后的name>&dir=<编码后的运行根目录>` | 核对该任务的路径、阶段、错误和实际产物 |
| `GET api/studio/project?name=<编码后的name>&dir=<编码后的运行根目录>` | 读取该项目固定的组装工程和光照贴图是否已生成 |

```json
{
  "dir": "/当前追踪的运行根目录",
  "directory": "/本次任务的运行根目录"
}
```

POST 使用 `Content-Type: application/json`；`dir` 必须取自刚读取的设置，过期时刷新后再操作。设置是实例共享的，切换会影响所有浏览者；沿用用户指定的目录，不擅自改掉无关实例。需要同时保留两个不同目录的视图时使用独立工作台 checkout 和端口；只换端口仍会共用同一份持久化设置。

打开 `<工作台根URL>?name=<编码后的name>`。页面的 `?dir=` 不会修改追踪目录，不能靠拼这个参数完成连接。确认页上选中的任务名、运行根目录与真实阶段一致；任务不存在时页面可能显示另一条任务，不能据此声称连接成功。已有文件时打开一项实际产物，未生成文件时展示真实等待／运行状态。

有浏览器工具时打开并检查页面，再给用户链接；没有打开浏览器的能力时提供链接并说明。若前端或远程访问不可用，报告具体原因并修复可恢复的问题，不能声称已打开；已在正常制作的管线继续运行。

## 角色项目预览

角色工作台用 `<工作台根URL>studio?project=<编码后的name>` 直接加载项目，无需用户再选文件。产物相对 `<dir>/<name>` 的路径由 [shared/studio-artifacts.ts](../shared/studio-artifacts.ts) 统一约定：组装工程为 `character-assembly/step01/character-assembled.kra`，原画为同目录 `character-assembled.png`；后续光照管线向 `lighting/normal.png`、`lighting/depth.png` 原子发布与该原画对应、同尺寸的贴图。

法线 / 深度生成尚未接入时维持“待管线生成”，不从研究归档或过程文件中猜选。产物出现后，用户点“更新项目”即可重新读取并自动绑定。工作台仅消费这些输出，打开页面不启动生图。所有角色和示例从项目栏加载，不能混用不同版本的原画和贴图。

## 运行、预览与巡检边界

通常仍按[总入口](workflow-details.md#总入口)从实际安装的 skill 启动制作，网页追踪同一目录。若改从网页发起，执行的是工作台 checkout 内的 skill，继承服务进程的 Codex、Python、Krita 显示环境及该 skill 的 `.env`；启动前对齐这些配置，尤其是保存原 thread 历史的 Codex 环境。仅让网页浏览产物不要求它具有模型凭据。不要同时通过 CLI 和网页启动同一任务。

网页可展示 CLI 产生的文件；“停止”按钮只控制由网页启动且仍由对应 worker 管理的任务。CLI 任务取消仍由 agent 核实并停止原进程及子进程。关闭页面不停止制作。

“任务与执行”页签负责选任务、启动、续跑和日志，展示各管线的待执行、进行中、已有产物、已完成或执行失败状态；选择管线后进入独立的“流程预览”页签并定位到对应位置。预览保留整张流程图，可展开 preparation、分组绘制／review／去重／补全、深度、raster 各步等真实进度，并查看 groups 树与产物。直接入口为 `?name=<name>&page=preview&stage=0`，`stage=0..6` 对应七条管线（最后为摆动物理）。旧归档缺少 `standard.png` 或完成记录时按已有文件展示；“已有产物”不等于当前已运行完成，不补造标记。配置页可只读浏览本地工作区、分支和提交差异；切换预览版本不会切换执行版本，展示的也是工作台 checkout 的配置，不是任务历史提示词快照。

页面刷新只更新展示，不能代替[每 2 小时巡检](monitoring.md)及主动恢复。把工作台 URL、checkout、端口、追踪目录及启动方式写入 `monitor.md`；巡检分别检查制作进程和页面，页面故障不触发绘图重置。交付时保留结果入口，不因为任务完成而关闭其他任务共用的工作台。

人物／衣服 raster 共用同一套展示组件；两轮复核展开在 step01，step02 只显示边缘精修。复核通过后无需执行的后续步骤显示为紧凑节点，明确标注“无需执行”，不会冒充已执行完成。每条绘制管线在横向流程旁共用一张最新 KRA 预览，按实际保存时间选择工程，读取其中的 `mergedimage.png`；缩略图按透明内容范围适配，点击后保留完整原尺寸画布。不会用控制图、旧导出 PNG 或诊断热图代表当前绘画进度。尚未保存工程时显示等待首次保存；未保存的笔画不会出现在预览中。review/repair 卡片展示报告结论与引用图片，点击完整报告后按引用位置显示图片；兼容任务内绝对路径、相对路径及 Markdown 图片，草稿明确标注，不能当作完成记录。过程文件仍可按需展开。
