【路径约定】
- 任务根目录：{uri:.}。工具结果给出绝对路径；正文写成相对路径的，以任务根目录为基准。涉及任务文件时，你在工具参数、shell 命令、写入的 JSON 和记录中都直接填写完整的绝对路径，可原样复用给出的路径；生图相关路径（参考图、保存路径）一律只接受绝对路径。
- 相对路径的基准取决于由谁解析：shell 命令和内置文件编辑工具按当前目录解析，当前目录默认是当前工作区，切换目录后随之改变；本流程提供的工具参数，以及程序读取的 JSON 和记录中的相对路径，则一律相对任务根目录 {uri:.}（例如 part-layering/groups.json），不能用 ../ 越出任务根。两者基准不同，所以任务文件统一写绝对路径，相对路径只用于在工作区内处理自己的草稿。程序保存记录时会自动转为相对任务根目录的路径，你无需自行转换。
- 报告中的 Markdown 图片链接例外，按 Markdown 惯例相对报告文件书写，以便报告移动后仍能显示。

【运行目录】
- 当前工作区：当前目录（shell 的初始工作目录）。草稿、中间图片、临时脚本及其他中间文件都放在此目录内，子目录按需要自由组织。
- 本管线目录：任务根目录下本次 section 的一级目录。正式输出目录：当前工作区的上一级目录。完整产物、报告及报告引用的图片放在正式输出目录；报告图片的位置自行选择，引用需能从报告解析。
- 程序准备的文件输入位于工作区的 references/；已有原图和上游产物按给出的路径直接读取。直接传入的正文或图片已在本次上下文中，无需再建立输入副本。明确指定的交付路径优先。
- 延续已有进度，不改写输入文件、各步的 .running／.completed，或 agents 中的请求、日志、会话配置。工作工程每完成一批实际修改就保存，便于查看最新进展；交付时保存到指定正式路径。
- 命令都在本轮内前台运行并结束，不用 nohup、setsid、disown 或 & 启动脱离本轮的后台进程；本轮结束或被停止时，这类进程无法被回收，结果也不会回到本轮。
