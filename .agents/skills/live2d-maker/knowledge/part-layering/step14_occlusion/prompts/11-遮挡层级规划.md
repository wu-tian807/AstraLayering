目标：在 preview.svg 已生成的基础上，为全部终止 part 确定深度和必要的显隐关系，逐件看图检查，交付独立于 groups.json 的完整 occlusion.json。规划的是当前参考姿势的绘制顺序。

## 先确定实际分层单元

- 读取完整 groups.json，以没有子节点的终止叶节点为本次 part 名单；有子节点的容器不另占绘画深度，没有 kind 或仍标为 group 的终止叶节点也需要覆盖。
- 父组说明提供范围和连接职责，具体深度必须落实到承担该区域的叶子完整 ID。父组的肩部、开口、接缝等职责由实际子件承接，不能用父组 SVG 代替子件，也不能给整条分支统一指定前后。
- groups.json 表示包含关系，树顺序、ID 段数和原结构预览的叠放顺序不决定绘制顺序。跨 group 的所有终止 part 在同一深度表内，数值越大越靠前。

## 先辨认区域归属，再判断前后

- 对实际相交的部件，先在原图上定位接触、接缝、开口及遮挡边界，再结合叶子和祖先 note、完整 SVG，确认每段结构和轮廓由谁承担。
- 原图中有明确遮挡边界的区域，覆盖者在前，被覆盖者在后。保留可见外轮廓、开口和线条的连续关系；不得为了透见、融合或保留补全色块反转真实遮挡。
- 连续肤色、贴身衣料、同材质无缝连接处，原图未必能区分两个 part 的分界。此时用节点的实体归属、连接和运动职责解释完整形体；不能仅因一段皮肤在原图可见，就断言它必归伸出的部件。
- outline-reduce 是描边、去重阶段保留的范围，也可能已从完整父稿复制；完整 SVG 是后续用于制作的完整形体。两者的差异只说明制作历史。旧轮廓的边界、补全路径的位置和辅助填色都不自动成为部件所有权或前后分界；新增补形也不自动属于后方。判断它承接什么结构、在哪个局部连接中起什么作用。
- 完整 SVG 的投影重叠可能来自连接余量、遮挡补全或绘制范围出入。重叠本身不证明原图中发生前后穿插。若形体超出职责，保留应有层序并在 note 标出待修位置，不用改深度把错误的形体藏起来。

## 连接处的通用原则

独立运动的相邻部件，常以局部搭接保持连接。先识别连接两侧的职责：

- **承接并覆盖接缝的一侧**持有该处应连续呈现的轮廓、内凹、开口或转折，并遮住另一侧的连接端。
- **伸入的一侧**保留自己完整的运动形体，在连接端伸到覆盖侧下方，局部余量随本件运动。

在原图没有明确相反遮挡时，连接区域按覆盖侧在前、伸入端在后规划。覆盖侧是谁，应从实际节点职责和形体判断，不按父子关系、躯干/附件身份、近端/远端或解剖名称套固定顺序。两端可以承担不同职责，同一部件在一处覆盖邻件，在另一处伸入另一邻件，并不矛盾。

连接处必须检查**最终由哪个叶子呈现走线**：覆盖侧持有的连接轮廓应能在正确层序下连续呈现，伸入端的封口和余量应藏在其下。若将该轮廓所在区域整体放后，会让伸入端反盖连接转折，就不能用“这是新增补形”或“原轮廓外都属后片”解释这一反转。连接轮廓尚未画完整时，标为形体待修；不要用 levels 代替补画或重新划定归属。

这是一条局部连接约束，不代表连接两侧的整条分支都在同一前后位置。远端和同支其他叶子仍按各自接触、交叉和运动职责独立判断。

## 汇总局部关系，确定全表

- 对明确遮挡、连接覆盖和前后夹层分别记录相关叶子及位置，汇总成全表的前后约束，再从后到前排序。互不重叠且无结构约束的部件，其相对顺序不需要虚构遮挡理由。
- 先尝试每件一个 level。局部关系出现环或矛盾时，回看是否误认了区域归属、把连接余量当作可见遮挡，或把父组/某一接点的关系推广到整件；不要立即按旧 outline 切前后片。
- 一个共同运动的完整 part 在当前姿势中，确实有区域位于另一件之前、另一区域位于其之后，且单一深度不能同时保留这些关系时，才用 levels 记录多个深度和文本区域。保留同一逻辑 part，不改部件树。
- 每个多深度区域写清位置、所负责的表面或连接轮廓、相关叶子完整 ID、前后依据及连续分界。与连接相关的区域必须保持覆盖侧和伸入端职责。不能仅以“原可见范围/新增补形”“同色路径/异色路径”划分，也不能为了消除 SVG 超范围或候选色块遮盖而增加深度。

## 隐藏结构

- hiddenInReference=true 的部件保留完整形体和自己的深度，依据结构职责安排层序。例如眼白、虹膜和高光位于眼睑后方，眼内内容的可见范围由上眼睑内缘和眼睛下缘（眼白下沿，有 lower_eyelid 时为它的上沿）围成的开口控制；嘴内结构同样依据唇开口安排。
- allowOutsideParent=true 时，按 note 的完整形体检查位置、邻接和归属，父轮廓只提供定位参考。

## 蒙版与剪贴

- 只有 hiddenInReference 部件（原图中不可见、需要默认隐藏的结构，如口内、眼内）才规划透明度蒙版或剪贴关系，限制其可见范围。
- 可见部件之间的遮挡只用深度表达，不规划蒙版。不得为“透见”“隐约可见”“融色”等效果规划蒙版；这类效果若按深度无法成立，在 note 中说明，由 raster step01 按深度处理。
- 规划蒙版或剪贴时，在 layers[].note 中写清被控制部件、控制部件的完整 ID、作用范围与默认显隐状态，并核对组内顺序与组外部件的穿插。跨深度的 part 用 levels 描述各区域，在 note 中说明哪些分片共享显隐控制。蒙版沿用所属层或组的关系，无需另建终止 part 或分配绘画深度。

## 逐件检查与提交

- 先看现有 preview.svg 与原图叠加，读取实际叶子名单和说明，再用 propose_occlusion 提交完整提案。查看候选预览，逐件查看完整 SVG 与原图叠加；连接、交叉、夹层及有争议的部位放大观察，必要时对照 outline-reduce 定位旧可见边缘。
- 用 check_occlusion_part 检查每个终止 part。在已有 note 中写出关键相邻叶子的完整 ID、具体位置、轮廓归属与前后依据，区分原图明确遮挡、无缝连接的职责推断和形体待修。检查候选是否反盖覆盖侧的连接走线，不能只确认数值顺序或总体外轮廓相似。
- 多深度部件逐区域核对，在检查 note 和 regions 中解释为何一个 level 不够、各区域与哪件穿插、分界为何成立；核对显隐控制与每个区域的层序相容。
- 候选仍使用完整 SVG，整件只放在最靠后的深度，多深度部件尚未切片，显隐蒙版也尚未应用。隐藏结构在此预览中露出时，结合开口或裁切规划判断；多深度候选的遮盖不能证明分片已正确，也不能单凭此现象反转层序。文本区域规划由 raster step01 实施，实际穿插和默认显隐需在其 KRA 中验证。
- 保持原部件树与 SVG，按现有叶子记录所需深度。连接余量或局部形状出入写成具体待修说明；仅在必要输入缺失、损坏或确无依据判断时，用 report_occlusion_problem 报告具体部件、位置和原因。
- 全部叶子及多深度区域检查完成后调用 submit_occlusion 交付。本步只规划，不绘画、不切片、不更改输入或另造输出字段。
