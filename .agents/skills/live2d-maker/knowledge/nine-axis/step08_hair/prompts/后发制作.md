## 目标是什么

1. 核心目标仍是拟合参考关键帧及转头动画。可见的头型、发面、发束走向、耳后轮廓、发尾落点与遮挡变化都要对应参考。后发加入后，整头应像同一个有体积的头部在转动；不能仅让外缘贴合，内部纹理却像不动的平面。缺少单独 right 参考时，依据正面发型和相反透视制作，保留原有两侧差异。
2. 后发通常承担较稳定的后脑体积，优先采用较小的位移、转动和局部形变，让原来被前发、侧发遮住的发面随转向自然显露。它不是完全不动，也不必跟前发同幅度扭曲。小幅形变加遮挡显露是优先尝试的方法，以参考和实际体积为准，不设统一幅度数值，不为减小运动而偏离关键帧。
3. 重点协调头顶：前发、侧发和后发的发根要顺着同一头壳连起来，过渡圆顺、厚度合理。按需要局部调整前面几缕发片的形状、层级、形变或画稿，修好露出的高点、凹口、缝隙和压扁；不把全部头发一起外扩，也不拿侧发或前发去硬补整块后脑。
4. 先判断现有画稿和拆分结构能否支持目标。能通过自然形变与合理遮挡达到目标，就沿用；若可见轮廓、描边或细发只能靠极端挤压才能塞回去，说明画稿或结构需要调整，直接在 Krita 修顺轮廓、重绘局部、拆分发缕或补足遮挡区域，再赋予自然运动。不能将瑕疵压到几乎消失，留下脏边、线宽突变或运动穿帮。保留原发型是保护视觉特征，不是要求原始像素不变；参考匹配、干净自然的可见边缘和连续运动优先。是否改画稿由实际需要决定，不强制每个角色重画后发。
5. 补齐与已制作前发、侧发、后发相关的独立投影和接收关系。投影跟随正确的发片，按当前接收部件裁切；尤其检查新露出的后发上，侧发投影与发缘是否协调，避免错位、悬空或重复压暗。

## 要保护什么

1. 可编辑 hair/bangs、hair/front_hair、hair/side_hair、hair/back_hair 及这些前缀下的阴影和专用 Warp，新增部件 level=hair。前发、侧发允许为整体协调作有理由的修改，保留已经建立的角色发型和可见参考关系，不无故推翻已有结果。脸、五官、耳朵、下颌、脖子和未制作的辫子、头饰保持原样。
2. 当前 KRA 与 hair.json 是工作依据。画稿修改在 Krita 保存，已有图层沿用 UUID，新图层显式绑定；不用独立 PNG 替换画稿，不回退到上游工程。投影保留独立图层和 caster/receiver 关系，不烘焙到脸或发片。
3. 不制作上下、四角或非零 Y。继承的脸部 Y/XY 数据原样保留。工作范围限本步工程、模型和检查记录，不修改工作流、工具或校验器源码；程序错误记录并返回 error。

## 自检查什么

1. 先在 Krita 核对当前后发及相关前发、侧发的实际内容、UUID、范围、绘制顺序、蒙版和投影。记下哪些部件需要变形或协调，以及是否需要改画稿、原因是什么。用 edit_nine_axis 显式注册需要的后发与阴影，正确组织 Warp、shadow、clip 和顺序；不假设工具会自动带上关联投影。
2. 对照当前 KRA 原形与关键帧描 source/target，保存在 outline/back/，区分可见轮廓、遮挡边界和需要推断的发根。已有有效描线可复用，局部返工只重描受影响区域，不重做已完成部分。先看完整后脑体积，再判断哪些区域主要靠遮挡显露、哪些需要较小形变、拆分或补绘。描线核对后用 edit 制作，本轮不使用 fit。
3. 后发独显检查完整体积、隐藏覆盖与纹理，再看前发＋侧发＋后发＋已完成脸部及对应投影的组合。参考比较使用同画布坐标、crop 和 scale 的 reference + edge，不重新对齐参考。叠加只用工具的 edge，不自行制作 blend 叠图；内部发流、高光、明暗和空间感用原色预览检查。未制作的辫子、头饰不混入判断。
4. 用 frames 检查 X={left_angle}、两侧中间值、0、X={right_angle}，全部 Y=0，并检查连续转头动画或更密的中间角度。重点看头顶连续性、近远侧厚度、耳后及发梢的显露顺序；在正常观看尺寸和局部放大时，可见描边、细尖和高光都应清楚连续，不能挤成亚像素碎边。不能后发僵住像贴板，也不能大幅挤压、剪切、拉伸或丢失后脑体积。端点贴合而中间穿插、露底、露出截断边、裂开、跳变或扁平，仍须修正；无翻折只是基本条件。
5. 暂时 hidden 投影区分形状与明暗问题，完成前恢复组合复查阴影随动、动态接收裁切及整体体积。若改了 KRA，保存后重新用工具读取；同步检查受影响的前发、侧发、后发和正面发型，不只检查补画的局部。
6. 整体造型、可见参考或头顶衔接仍有明显问题，就继续调整；工具成功、网格合法或后发运动很小都不等于完成。保存 KRA、hair.json，并在 notes.md 记录实际协调、画稿是否修改及原因、参考与过渡检查结果和仍有的限制。完成返回 {"error":null}，不能完成则返回 {"error":"具体原因"}。
