# Live2D Layering

作为总控，按本目录的编号节点执行任务。`流程.yaml` 声明输入、选项与产物，节点提示词交给对应 worker；生图由总控直接调用 imagegen。

## 开始运行

确认用户提供了本轮**绝对工作根目录**及根目录 `流程.yaml` 声明的必要输入；缺项时集中询问。可选输入按用户实际提供情况绑定。

读取根目录的 `流程.yaml`，绑定外部输入，创建工作根目录。已有的 `options.yaml` 保存本轮选项；用户本轮明确选择优先，交负责判断的 worker 写入。

默认执行本目录全部已建立的编号节点；用户可以指定起止节点。执行顺序由目录编号决定，输入、条件和产物由各节点的 `流程.yaml` 决定。

## 读取节点

- 按目录前缀的数字层级排序，如 `1.2` 在 `1.10` 前；分组目录展开到实际节点。同编号且带 `.parallel.` 的节点并行，全部完成后继续下一编号。
- 每个节点先读自己的 `流程.yaml`。`run` 相对该 YAML 定位执行目录；目录有编号子步骤时继续展开，到了实际任务才读取提示词与模型。普通任务省略 `run` 时执行当前目录。
- 普通节点的 `inputs.<名称>` 引用本轮外部输入；循环模板中的同类引用取本次循环已绑定的输入。`nodes.<id>.<名称>` 直接引用已完成节点的产物，普通文件路径相对工作根目录，`asset` 相对节点 YAML。`required: false` 的缺省输入标为“未提供”。
- `if` 成立走 `then`，否则走 `else`。分支继承节点输入，并加入分支自己的输入。条件中的输入名指已绑定的本节点输入；`options.<名称>` 从本轮 `options.yaml` 读取，缺值先完成对应判断节点。
- 输出中的 `inputs.<名称>` 指本节点已绑定输入，`nodes.<id>.<名称>` 指上游产物；其他输出路径相对工作根目录。普通节点结果可通过 `nodes.<本节点id>.<输出名>` 引用，循环各项直接记录实际文件路径。
- `writes_options` 由该 worker 使用提示词指定的工具写入工作根目录的 `options.yaml`；总控读取结果后继续。这是运行配置，不是节点产物。

分支声明保存路径且复用已有输入时，按声明的路径与格式保存该输入；图片图号与用途按节点配置和提示词绑定。

完整格式见 [Workflow DSL](docs/workflow-dsl.md)。遇到 `review`、`foreach` 等配置时读取对应规则；可执行任务以本目录实际节点为准，文档中的示例用于解释格式。

## 派发语言 worker

只读取执行资料目录内的语言 `.model` 标记，从文件名最右侧拆出推理强度。例如 `gpt-6-sol-xhigh.model` 对应模型 `gpt-6-sol`、强度 `xhigh`。

新 worker 用 `spawn_agent` 显式传入模型与推理强度，`fork_turns: "none"`。串行节点使用相同 `worker` 名时，通过 `followup_task` 继续原会话；不同名称分别建立会话，省略 `worker` 时以节点 `id` 区分。

并行分支共用已有 `worker` 时，从该 worker 在分支前已完成的上下文分别 fork。当前 `spawn_agent(fork_turns: "all")` 继承调用者的上下文与模型，因此总控把分支交接清单交给原 worker，由它发起各分支并返回子 agent ID；总控继续跟进。分支内的续做与返修交给各自的子会话，汇合后将各分支产物路径交回原 worker 继续串行任务。共用 worker 的模型与推理强度保持一致；尚无已有会话时，各分支按新 worker 建立。详细规则见 [会话与 fork](docs/workflow-dsl.md#会话与-fork)。

记录实际 agent ID，等待依赖任务完成后再推进。

交接只包含以下内容，提示词通过路径读取：

```text
工作根目录：<绝对路径>
提示词：<绝对路径>
输入：<用途或图号＝实际绝对路径；可选缺项写“未提供”>
输出：<用途＝相对工作根目录的路径>
读取指定提示词并执行，命令的工作目录设为上述工作根目录。
```

按实际节点填写；只有 `writes_options` 的任务将“输出”行换为“写入选项：<字段名>”。用户对该任务的明确要求一并交接。worker 的任务依据是这份交接与指定提示词，Skill 和规划文档由总控使用。

`foreach` 的分组与模板路径由流程 YAML 声明，总控逐项展开模板的编号步骤，直接交接实际任务的提示词路径。循环目录只存调度配置；模型与 `worker` 在模板任务中声明，同名 worker 跨组复用。分组、排序及产物传递按 [DSL 动态派发](docs/workflow-dsl.md#8-按产物动态派发)处理。

## 执行生图

`imagegen.model` 标记总控直接调用生图工具。读取节点 `imagegen.prompt` 指定的文件，按图号传入实际参考图，生成一次，将返回图保存到声明的输出路径。`imagegen.when` 决定本次是否需要生成。

节点声明的 YAML 或文本参考输入，读取后以带名称的输入资料附在生成提示词后；图片使用参考图参数传入。生成提示词保持文件原文。

参考图只确认成功保存、可正常读取，随后交给下游使用。额外的质量审查、重绘或手工修图由用户提出；工具失败则报告具体卡点。

## 完成与续跑

按节点提示词完成任务内已有的自查；独立 review 仅由流程中的显式声明触发。总控确认声明的文件或选项已交付；必要输入、模型能力或产物缺失时，说明所在节点及缺项。

在工作根目录的 `运行记录.md` 简记输入绑定、选项与分支、节点状态、worker 及其 fork 子会话 ID 和实际产物路径。续跑据此恢复本轮产物与会话，输入改变时重新处理受影响节点。

结束时给出实际产物链接、完成位置和遇到的卡点。
