# 部件表面归属、隐藏补全与移动

2026-10-21；验证对象为 Jianma 1024×1536 分层皮套、已有左右手替换，以及独立斜面遮挡标定图。方法已在原人物工作台和 AstraLayering 专业工作台的部件试验使用。本节不替代原画绘制，也不宣称任意新姿势的隐藏几何已经恢复。

## 数据与流程

一张整图法线／深度描述当前可见表面。将它按像素坐标直接分给所有重叠图层，会把手部的方向和深度误写进背后的衣服。正确输入包括原图层的完整颜色与 alpha、穿戴蒙版、前后叠加顺序，以及尺寸和坐标一致的整图法线／深度。

1. 在原始 UV 中按前到后累积透射率。部件有效 alpha ≥0.65、前方透射率 ≥0.8 的像素接收该坐标的法线与深度，作为固定实测样本。
2. 普通表面以实际 alpha 覆盖，保留手指间隙与衣物孔洞。需要补成封闭表面的线条组使用显式轮廓策略；小断口封合、封闭内部填充与数据外扩均为通用操作。显式蒙版切口仍保持开放，不用矩形排除眼睛／嘴巴周围的皮肤。
3. 在同一图层的 alpha 连通区域中传播可见种子，随后求解固定已知边界的离散 Laplace 场。透明孔洞为无流边界，不借用相邻物体的值。法线与深度共用稀疏 Jacobi-PCG 求解，避免固定少量迭代留下大范围接缝；结果保持原始像素尺寸。
4. 完全没有种子的独立区域只使用同部件的样本均值估计；整个部件无样本时退回正面法线与中间深度。它们始终是未知／估计，不变成实测。
5. 缓存部件局部贴图。移动或形变时，颜色、法线、深度与有效遮罩使用同一最终映射。方向数据做局部逆转置；平移不改法线，二维旋转同步旋转法线方向，前后偏移加到深度上。运动时不从屏幕上新邻居重新取样。

原人物工作台在加载时补全；专业工作台在「准备部件贴图」时分批读取完整像素，再通过 Worker 补全。切换贴图会取消仍在准备的旧试验。移动预览不逐帧重新求解。专业工作台继续使用 MToon 与 Three.js 的光照／投影，并未因接入部件补全更换明暗公式。

## 已验证

| 对照 | 结果 |
| --- | --- |
| 斜面隐藏宽度 64／128／256 px | 旧固定 96 轮算法最大深度误差为 4／22／43 个 8-bit 等级；新求解均 ≤1，已知样本固定 |
| Jianma 眼睛开合 1／0.75／0.5／0.25／0 | 原画 RGB 与 alpha 逐像素一致；闭眼、左右灯与投影开关对照通过 |
| 真实右手六层移开、移到脸旁、使用已有左手六层替换、复位 | 新旧算法的原画 RGB／alpha 一致；实测贴图值不变；隐藏区域连续性指标改善 |
| 专业工作台实际 KRA | 原生分层快照能等价重建合成图；手部平移、旋转、替换与复位通过，贴图／PNG 保持 1024×1536 |

专业工作台右手有效像素 5611，其中 3072 可归属实测，约55%。其余为补全或估计；该比例不证明生图法线本身准确。手移到脸旁的试验直接改变手部变换与绘制顺序，不是手臂 IK、九轴或碰撞测试。

## 替换与前后关系

已有替换部件应使用自己的颜色、局部法线／深度和来源对应关系，再映射到目标位置。不能把目标位置的脸部深度当成新手势的深度。本次用已有对侧手部验证缓存复用；未验证新绘制握拳、手掌翻面或模型生成的全新形状。

专业试验中的「前后」调整表面深度与投影；「移到前层」调整颜色／数据的绘制顺序。二者分工明确。制作动画时应把前后顺序和深度作为同一姿态的约束，不能让画面上位于脸前的手在深度里却躲到脸后。

## 适用边界

- 已画出的隐藏颜色是前提。接收图层在揭露区没有颜色／alpha 时，贴图补全不会生成原画。
- 有周围样本的连续皮肤、衣料、发片适合平滑估计。大褶皱、折返、尖锐折面与完全无样本区域需要补充地图或艺术约束；平滑不等于真实。
- 切换新几何应生成或绘制对应部件地图，必要时与同一表面的邻近样本衔接。不能把完全不同表面的临近填充称作通用几何恢复。
- 专业试验当前接受普通8位 sRGB 绘画层与叶子透明蒙版。组蒙版、透明度继承、依赖背景的混合、滤镜／变形蒙版继续由原生 Krita 编辑保留；快照不能等价重建时不启用部件试验。不是以近似渲染替代原生显影。

## 复验与实现

专业工作台：打开 Jianma 或当前项目 → 部件试验 → 准备部件贴图 → 选择手部 → 移动／旋转／前后／替换 → 复位。原画、法线、深度与光照仍使用同一个画布。

实现：前端交互位于 `web/studio/surface-coverage.js`；贴图归属与补全由 skill 的 `shared/character-render/part-maps.js`、`harmonic-fill.js` 维护，原生快照由 `shared/krita/native/astra_layers.py` 提供。前端直接消费共享实现，skill 可独立安装运行。

定向复验：`web/tests/studio-surfaces.test.ts`。历史原生与浏览器辅助检查脚本已删除，可从 Git 提交记录查阅；原工作台对照脚本为 `verify-character-hand-surfaces.mjs` 和 `verify-character-surface-ownership.mjs`。临时图片与完整指标保留在忽略的检查目录，不作为新角色源文件提交；软件 GPU 检查不代表用户设备帧率。
