# 图层分层契约（草案 v0.1）

> 历史格式，已停止用于主工作流；仅供理解早期示例。现行流程使用 SVG 原生分组与绘制顺序，见 [workflows](../workflows/readme.md)。

---

## 1. 文档结构

- 根节点是一个 `<svg>`，`viewBox` 与参考图分辨率一致。
- 一份 manifest，内嵌为 `<metadata id="layer-manifest">`，是一个数组，顺序 = 从底到顶的叠放顺序。

## 2. manifest 字段

| 字段 | 说明 |
|---|---|
| `id` | 英文 slug，唯一，等于对应 `<g id>` 的值 |
| `name` | 人类可读标签 |
| `category` | 自由文本语义分类，模型自己判断 |
| `rank` | 整数，从 0 递增，等于该层在文档中的实际顺序下标 |

不要求模型给出 bbox / path 数量 / 字节数 / 哈希，这些由脚本从最终 SVG 里量出来。

## 3. 图层结构

- 每个部件是 `<svg>` 的直接子 `<g id="{id}">`。
- `<g>` 上镜像写 `data-name` / `data-category` / `data-rank`。
- 一层能引用的资源，不能是另一层私有声明的资源。
- 遮挡区域补全，使该层单独显示时是完整部件。

## 4. 允许的情况

- 拼接处允许小范围重叠。
- 图层内部复杂度不设上下限。
- 部件可以自行拆成多个按顺序排列的碎片，各自登记 `id` / `rank`。

## 5. 命名建议

id 尽量带可复用子串（如 `eye_L_iris_highlight`），方便同角色下次生成时延续标注。
